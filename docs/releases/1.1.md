diagnostics, and workspace inspection foundations from beta into the stable

## What Changed From Product 1.0

Product 1.0, represented publicly by `0.1.0`, proved the task-first baseline:
turn a goal into a visible plan, run local tasks, and inspect the result through
Audit.

Product 1.1 changes the main loop into a Router-first conversation and evidence
workflow:

```text
user input
  -> Runtime Input Router
  -> read-only answer, ASK/confirmation answer, guidance, revision command,
     archived-plan inspection, or execution handoff
  -> durable Conversation / Activity
  -> Audit, diagnostics, workspace inspection, and file evidence
```

The user no longer has to know whether an input should become a new plan,
guidance, a question, an ASK answer, a task revision, or execution work before
typing. Plato routes the input and records the outcome.

## Added In This Release

### Runtime Input Router

- Routes one Main Page input surface across questions, guidance, ASK answers,
  confirmation answers, plan/task revision, and execution handoff.
- Keeps workspace-changing behavior behind commands rather than direct Router
  writes.

### Durable Conversation And Activity

- Persists user input, Router interpretation, read-only answers, ASK cards,
  confirmation flows, task updates, command outcomes, and plan archive events.
- Makes Conversation the primary user-visible history surface.

### Read-Only Inquiry

- Answers questions about the current session or workspace without mutating
  files or task state.
- Records no-effect answers and evidence references where available.

### ASK And Confirmation Routing

- Shows Router-generated question cards in the Conversation flow.
- Persists both the prompt and the user's answer as conversation content.

### Contract Revision Commands

- Adds command-backed plan/task refinement and guidance paths.
- Separates read-only answers from execution handoff.

### Workspace Inspection

- Adds git status, changed-file projection, structured diff entry points, and
  file viewer paths.
- Uses renderer-safe labels and Audit-linked evidence for local workspace work.

### Token Usage Analytics

- Adds local token usage recording and summary foundations for session and
  workspace review.

### Precision File Tools

- Adds line-range reads, search, guarded line-range replacement, append
  operations, and changed-line evidence foundations.

### Archived Plan Access

- Keeps completed or archived plans reachable from Conversation.
- Opens archived plans in a Plan & Progress view close to the original active
  plan page, with Audit entry points.

### Frontend Interaction Runtime

- Improves submit responsiveness, pending-row behavior, route-return focus,
  overlay close-return focus, and Conversation scroll stability.
- Fixes the installer-smoke blocker where submitting while reading history could
  force Conversation to the bottom.

## Changed Behavior

- Stable now points to Product `1.1`; `0.1.0` remains the older Product 1.0
  baseline.
- The input composer is a routed product input, not only a plan/task text box.
- Conversation, Activity, Audit, diagnostics, and workspace inspection are the
  main trust surfaces.
- Read-only questions do not create tasks unless execution work is required.
- Plan and task changes go through auditable commands.
- Release packaging uses explicit release versions and excludes smoke/test
  assets from public DMGs.

## Known Caveats

- The app is unsigned.
- The app is not notarized.
- macOS Gatekeeper may block normal opening.
- The release is macOS Apple Silicon only.
- This repository is not a source-code mirror.
- Web retrieval is configuration-dependent and should be treated as a capability
  foundation, not a universal default.
- Signing, notarization, auto-update, remote execution, broad MCP integration,
  multimodal input, and marketplace-style distribution are outside this release.

## Recommended First Test

1. Open Plato in a test workspace.
2. Create or open a local project with Git initialized.
3. Ask a small question about the current session and confirm it appears in
   Conversation as a read-only answer.
4. Start a low-risk task and inspect the visible task plan.
5. Open workspace inspection to review git status, a changed file, and a diff.
6. Open Audit Page evidence after activity exists.
7. Check token usage summaries after AI-backed activity.
